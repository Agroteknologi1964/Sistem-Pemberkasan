Login & siklus JWT

1
GET / menerima request routes/web.php
Route / tidak punya controller — langsung redirect()->route('login'). Inilah sebab halaman welcome Laravel tidak pernah tampil.
2
Middleware berlapis: security → throttle → guest.jwt bootstrap/app.php
Header keamanan dipasang dulu, lalu throttle:login-page (30 req/menit per IP), lalu RedirectIfAuthenticated yang membaca cookie jwt_token. Kalau token masih valid → langsung ke dashboard sesuai role.
3
Halaman login tampil resources/views/auth/login.blade.php
Form POST ke login.post dengan CSRF token. Di titik ini tema gelap/terang sudah dipasang oleh theme.js sebelum paint.
4
POST /login — throttle:login SecurityServiceProvider
Kunci rate limit: email(case-insensitive) + IP. Maks 5 percobaan/menit. Percobaan ke-6 → 302 + pesan error, atau 429 bila request JSON (API).
5
LoginRequest memvalidasi input app/Http/Requests/Auth/LoginRequest.php
Email wajib format valid & maks 255 char, password min 6 karakter. Gagal → balik ke form dengan pesan Indonesia.
6
JWTAuth::attempt() membuat token AuthController::login
Token ditandatangani HS256 dengan JWT_SECRET (64 char). Kalau secret kosong → exception "Secret is not set" — persis error yang Anda temui saat seeding.
✕
Cabang gagal: akun nonaktif
is_active = false → token langsung di-invalidate (masuk blacklist) dan user dikembalikan ke form dengan pesan "Akun Anda tidak aktif."
✓
Sukses: token disimpan di cookie HttpOnly JwtAuthenticate::makeJwtCookie
Cookie jwt_token, HttpOnly (tidak bisa dibaca JavaScript), SameSite=Lax, dan Secure otomatis saat APP_ENV=production. Masa berlaku = JWT_TTL (1440 menit / 24 jam).
7
Redirect sesuai role redirectByRole()
Admin → /admin/dashboard. User → /user/folders/{rootFolder}. User tanpa root folder akan kena 404 dengan pesan hubungi admin.
8
Setiap request berikutnya: JwtAuthenticate app/Http/Middleware/JwtAuthenticate.php
Baca cookie → kalau TokenExpiredException, otomatis refresh() dan pasang cookie baru (sliding session). Kalau token invalid → hapus cookie + redirect ke login.
9
Auto-refresh di background layout app.blade.php
Setiap 20 menit, browser memanggil POST /auth/refresh agar pengguna tidak tiba-tiba ter-logout saat sedang mengisi form.
10
Logout → token di-blacklist AuthController::logout
JWTAuth::invalidate() memasukkan token ke blacklist (karena JWT_BLACKLIST_ENABLED=true) sehingga tidak bisa dipakai ulang, lalu cookie dihapus dengan Max-Age=0.

Bagaimana akses folder ditentukan

A
Admin — selalu punya akses penuh
User::canAccessFolder() langsung return true jika role === 'admin'. Admin melihat semua folder lewat query Folder::whereNull('parent_id').
B
User — hanya folder yang di-assign di pivot
canAccessFolder() mengecek folder_user. Saat user dibuat, UserObserver otomatis membuat root folder bernama sama dengan user dan meng-attach-nya.
C
Navigasi ke subfolder memakai getAncestorAccessFolder()
User bisa menembus subfolder, sub-subfolder, dst. — tetapi hanya selama ada ancestor yang di-assign langsung. Middleman ini menelusuri parent berantai sampai ketemu ID yang ada di pivot.
!
Celah: akses tidak berantai ke bawah secara eksplisit
Assign ke folder induk = otomatis bisa ke semua anaknya. Tapi tidak ada cara memberi akses ke subfolder tanpa memberi akses ke induknya — di UI admin, pilihan hanya per folder.

Alur upload PDF (admin saja)

1
Admin membuka modal upload FolderManager::openUploadModal
Folder tujuan = folder yang sedang dibuka. Kalau belum memilih folder, upload ditolak dengan pesan "Pilih folder tujuan terlebih dahulu."
2
Lapis 1 — validasi Livewire saveUpload()
required|file|mimes:pdf|max:{MAX_FILE_SIZE}. Batas dibaca dari config('app.max_file_size') yang kini benar-benar terhubung ke .env.
3
Lapis 2 — cek isi file (magic bytes) FileService::upload
Membaca 1024 byte pertama, wajib mengandung %PDF-. Ini menutup celah file berbahaya yang dinamai .pdf agar lolos mimes:pdf.
4
Lapis 3 — batas ukuran di dua level php.ini + nginx.conf
Rantai harus konsisten: MAX_FILE_SIZE=20480 (20 MB) ≤ upload_max_filesize 20M ≤ client_max_body_size 24M. Kalau Nginx lebih kecil, upload besar ditolak sebelum sampai ke PHP dengan error 413.
✓
Simpan ke storage tanpa memuat ke RAM writeStream()
Path dibuat documents/{folder_id}/{uuid}.pdf — nama asli tidak pernah dipakai di disk, jadi tidak ada path traversal. writeStream() menggantikan file_get_contents() yang dulu berisiko OOM di RAM 2 GB.
5
Verifikasi file benar-benar ada, baru catat ke DB
Kalau exists() gagal, lempar exception — lebih baik error jelas daripada baris database tanpa file.
6
Nama tampilan disanitasi & dipotong 180 char
Karakter selain huruf/angka/spasi/titik/strip dibuang. Kosong → fallback "dokumen".

Alur akses file saat dibuka

→
GET /user/files/{id}/preview atau /download FileController
File::findOrFail() → canAccessFolder($file->folder) → 403 bila tidak berhak. File tidak disajikan langsung dari public/, jadi URL storage tidak bisa ditebak.
→
Stream dengan header aman FileService::stream
Content-Disposition disanitasi (cegah header injection lewat nama file), X-Content-Type-Options: nosniff, dan nama UTF-8 dikirim lewat filename*= sesuai RFC 6266.
Sisa risiko: PDF asli masih bisa mengandung JavaScript berbahaya (PDF aktif). Untuk dokumen dari pihak luar, pertimbangkan menonaktifkan preview inline dan selalu memaksa attachment (download), atau menjalankan PDF melalui sanitizer.
